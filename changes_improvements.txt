1. GENRE QUESTION — DECISION: KEEP TOP-GROSSING AS-IS
-----------------------------------------------------
Do not switch to genre-stratified top-free. Reasons:

a) Direct precedent: Petrovskaya & Zendle (CHI '22) sampled exactly the top-50
   top-grossing games. You can cite the frame instead of defending a custom one.
b) Construct alignment: top-grossing is where monetization-driven DPs
   concentrate (Petrovskaya: 88% of top-grossing mobile had >=1 problematic
   technique; casino/RPG densest). Your badge targets exactly these games.
c) The claim changes from "audit across the mobile game landscape" to "audit of
   top-grossing mobile games" — which is the claim you can actually support,
   and arguably the more policy-relevant one (these games have the players).
d) Genre-stratified top-free would add coverage (racing, music, word...) at the
   cost of chart relevance, and those genres are precisely where Zhang found
   the fewest DPs anyway.

3. PLAN CORRECTIONS (from your last summary — silent regressions caught)
------------------------------------------------------------------------
- Pilot is NOT "a random 500": it is 300 random + 200 keyword-targeted, strata
  tagged and analyzed separately. Random -> base rates; targeted -> rare-class
  coverage (Social especially; Zhang's own data shows it is sparse).
- "Validate the teacher and maximize prompt scores" = TWO activities, TWO sets.
  Split 300 dev / 200 test BEFORE any prompt work; tune on dev only; ONE frozen
  run on test = the reported number. Same-set tuning+validation = contaminated
  number a reviewer will catch.
- Missing step between prompt validation and training: mass-label 200k ->
  observability frequency plots -> scope label set -> THEN decide subclass
  heads -> THEN train. Prevents last cycle's discover-imbalance-after-the-fact.
- Pilot random stratum and all base rates come from text-filtered but
  NOT ML-filtered reviews (binary classifier's 0.849 recall would bias rates,
  disproportionately dropping rare patterns).
